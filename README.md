# Decode the Data — اكتشف البيانات واكتشف مسارك

منصة تعليمية تفاعلية لورشة تعريفية بمسارات البيانات. يمر المشارك بست محطات مترابطة يبني فيها نظامًا يتوقع ازدحام مطعم **DataBite** الخيالي على كورنيش جدة، ثم يرى النظام المكتمل، ويواجه تحدي رمضان الأخير، ويستكشف المسار الأقرب لاهتماماته.

- بدون تسجيل أو تثبيت، وبدون كتابة كود
- عربي أولًا (RTL) مع المصطلحات الإنجليزية عند الحاجة — وكل مصطلح قابل للضغط يفتح شرحه
- يحفظ التقدم تلقائيًا على الجهاز (LocalStorage) — يدعم الاستكمال والرجوع والبدء من جديد
- نسختان: **نسخة الورشة** (~25 دقيقة) و**النسخة الكاملة** (~45 دقيقة)
- يشتغل بدون إنترنت بعد أول زيارة (PWA) على نسخة GitHub Pages

## القرارات تبني المشروع فعليًا (الأهم)

كل محطة تقرأ مخرجات اللي قبلها من **سلسلة حسابات واحدة** (`src/data/project.ts`) مبنية على قرارات المشارك نفسه — ما فيه نتائج ثابتة مكتوبة مسبقًا:

| المحطة | قرار المشارك | يؤثر فعليًا على |
|---|---|---|
| هندسة البيانات | طريقة معالجة 12 خانة مفقودة في الأسابيع الأربعة (متوسط نفس الساعة / متوسط عام / حذف / صفر) | الجدول نفسه ← كل الإحصاءات ← النموذج ← توقع ليلة العيد |
| تحليل البيانات | الاستنتاج (وصف النمط / ادعاء سبب) | التقرير + مراجعة الحوكمة |
| علم البيانات | الخصائص + المنهج (يشمل خيار التسرّب «عدد الموظفين») | ما يراه النموذج ← دقته ← توقع العيد |
| هندسة تعلم الآلة | إعداد التدريب (أمين / أسبوعان فقط / نموذج «حافظ» يُقيَّم على نفس بياناته) | النموذج والتقييم المعلن مقابل الحقيقي |
| ذكاء الأعمال | المؤشرات + خطة موظفي ليلة العيد | النتيجة الحقيقية: عملاء زعلانين، انتظار، رواتب، خسارة |
| الحوكمة | — | تراجع كل ما سبق وتكشف المشاكل الناتجة عنه، مع «ارجع وصلّح» |

**ثلاث درجات للقرار:** الأفضل · مقبول مع تكلفة (يكمل وأثره يمشي للأمام) · ضار (يعرض العاقبة محسوبة، مع «ارجع وصلّحها» أو «كمّل وشوف الأثر»).

**كيف نحكم بعدل؟** البيانات تعليمية ونعرف «الواقع» فيها (`TRUTH`، و`FUTURE_WEEK` = أسبوع جديد لم يره أي نموذج، و`trueExpected` لليلة العيد). فنقيس الخطأ الحقيقي للنموذج على أسبوع جديد، ونحكم على خطة التوظيف مقابل طلب ليلة العيد الحقيقي — مو مقابل توقع النموذج.

**اختبارات آلية:** `npm test` (Vitest) — 15 اختبارًا تثبت أن كل قرار يغيّر النتائج اللاحقة فعليًا (مثلًا: التعويض بصفر يخفض توقع العيد ويزيد الخطأ الحقيقي؛ التسرّب يعطي اختبارًا أفضل من الواقع؛ النموذج الحافظ يعلن ±0 وخطؤه الحقيقي ~±3.9)، بالإضافة لاختبارات ترحيل التقدم المحفوظ.

| الميزة | وين |
|---|---|

| **شخصيات الفريق** — شخصية مرسومة لكل تخصص + أم فهد صاحبة المطعم، والفريق يصفق في النهاية | كل المحطات |
| **قرار أخلاقي + نظام حماية البيانات الشخصية** | حوكمة البيانات |
| **خارطة طريق «وش أسوي بكرة؟»** — مواضيع، مصادر مجانية، برامج سعودية، أول مشروع | اكتشف مسارك |
| **قاموس المصطلحات** — المعنى العربي، شرح بسيط، مثال من المطعم، ليش يهم، ومين يستخدمه | كل الشاشات |
| **شرح بمستويين** — «الفكرة ببساطة» + «استكشف أكثر» في كل محطة | كل المحطات |
| **مسار البيانات (Data Lineage)** — تفاعلي، مع «تتبّع رقمًا واحدًا» من الكاشير إلى قرار التوظيف | النظام المكتمل |
| **ماذا لو؟** — اليوم، الساعة، العيد، الراتب، الفعاليات، العروض، ونشاط إضافي يدوي؛ يحدّث التوقع والمطعم الحي ومؤشرات اللوحة | النظام المكتمل |
| **أنت بنيت هذا النظام** — قرار كل محطة وأثره المحسوب، مع «عدّل القرار» | النظام المكتمل |
| **إنجازات** تُكتسب من نتائج حقيقية (مثلًا «صانع القرار» فقط إذا نجحت خطة ليلة العيد فعلًا) | الرأس + النظام + الختام |
| **اكتشاف المسار** — تقييم المهام + 5 أسئلة أسلوب عمل + إشارات خفيفة مما فعلته؛ أعلى 3 مسارات بنسبة توافق، ومقارنة مسارين | اكتشف مسارك |
| **وضع المقدّم / البروجكتر** — خط أكبر، تباين أعلى، نقاط للشرح، أزرار تنقل كبيرة، ومؤقت لكل محطة | زر «وضع المقدّم» |

## التشغيل محليًا

المتطلبات: Node.js 18 أو أحدث.

```bash
npm install
npm run dev          # خادم تطوير على http://localhost:5173
```

## البناء والنشر

```bash
npm run build         # بناء عادي في dist/  (للنشر على Vercel / Netlify / GitHub Pages)
npm run build:single  # ملف HTML واحد مستقل في dist-single/index.html
```

- **Vercel / Netlify:** اربط المستودع، أمر البناء `npm run build`، ومجلد الإخراج `dist`. لا يحتاج أي متغيرات بيئة أو خادم.
- **GitHub Pages (مُعدّ مسبقًا):** المستودع فيه `.github/workflows/deploy.yml`. فعّل مرة وحدة: **Settings → Pages → Source: GitHub Actions**. بعدها كل `push` على `main` يبني الموقع وينشره تلقائيًا على `https://<username>.github.io/<repo>/`.
- **ملف واحد:** `dist-single/index.html` يعمل حتى بفتحه مباشرة من الجهاز — مفيد كنسخة احتياطية في الورشة لو انقطع الإنترنت (الخطوط تتحول للخط الافتراضي بدون إنترنت).

## وضعا الاستخدام

| الوضع | كيف |
|---|---|
| **ذاتي** | المحطات تُفتح بالترتيب. كل شرح وتلميح موجود داخل الموقع. |
| **نسخة الورشة / الكاملة** | يختارها المشارك بعد قصة المهمة، ويقدر يغيّرها من خريطة الرحلة. في نسخة الورشة تُنجز بعض الخطوات تلقائيًا (وتبقى قابلة للعرض). |
| **وضع المقدّم** | زر «وضع المقدّم» في الشريط العلوي (شاشات ≥ 768px): يفتح كل المحطات، يكبّر الخط ويرفع التباين للبروجكتر، يُظهر «نقاط للمقدّم»، وشريط سفلي فيه أزرار السابق/التالي ومؤقت (الهدف: 4 دقائق للمحطة في نسخة الورشة، 7 في الكاملة). |

لا يوجد تزامن لحظي بين الأجهزة (غير مطلوب في هذه النسخة).

## البنية التقنية

**Vite + React 18 + TypeScript + Tailwind CSS 3.** بدون خادم وبدون مكتبات رسوم خارجية — الرسوم البيانية مكونات SVG خفيفة مكتوبة يدويًا.

> ملاحظة: البرومبت اقترح Next.js. اخترنا Vite لأن المنصة تطبيق صفحة واحدة بالكامل على جهة العميل (لا SSR ولا API)، فـ Vite أبسط وأسرع ويُنتج ملفات ثابتة تُنشر في أي مكان. نقل المكونات إلى Next.js لاحقًا مباشر لو احتجتم.

```
src/
  data/
    dataset.ts     بيانات DataBite الموحّدة (جدة) + أسبوع رمضان + الإحصاءات المحسوبة منها
    model.ts       نموذج انحدار حقيقي يتدرب في المتصفح + التقييم + إعادة التدريب لرمضان
    stations.ts    المحطات الست، الشخصيات، وخارطة الطريق لكل مسار
  state/store.tsx  الحالة المشتركة + الحفظ في LocalStorage + النسخة (ورشة/كاملة) + فتح المحطات
  components/      Shell (الرأس، إطار المحطة، الخطوات، شريط المقدّم) · LiveRestaurant · Consequence
                   Avatar · Glossary · Dashboard · charts · ui · Icon
  screens/         Intro · CompletedSystem · Ramadan · CareerDiscovery · Completion
  stations/        المحطات الست
public/            أيقونات التطبيق (PWA)
.github/workflows/ النشر التلقائي على GitHub Pages
```

### البيانات المشتركة
- فرع على كورنيش جدة، من 18 مايو إلى 14 يونيو 2025: 4 أسابيع × 7 أيام × 12 ساعة عمل (12:00–23:00) = **336 سجلًا ساعيًا**، مولّدة بشكل حتمي (seeded) فكل الزوار يشوفون نفس الأرقام.
- الفترة تشمل **ليلة عيد الأضحى** (5 يونيو، +50% عن خميس عادي) و**يوم 27 مايو** (نزول الرواتب، +48% عن ثلاثاء عادي) وثلاث **فعاليات على الكورنيش**.
- الحقول: `id, date, weekday, hour, dinein, delivery, orders, promo, event, eid, payday, temperature, staff`.
- أسبوع رمضان منفصل (فبراير 2026) لتحدي انحراف البيانات: ذروة عند الفطور (18:00) وبداية السحور (23:00).
- كل رسم، جدول، تقرير، وتوقع في الموقع محسوب من هذه البيانات نفسها — تقرير المحلل، ميزات عالم البيانات، النموذج، ولوحة الإدارة كلها متسقة.
- `staff` (عدد الموظفين) مرتبط بقوة بالطلبات لكنه **نتيجة** وليس سببًا — يُستخدم لتعليم «الارتباط ليس سببية» وتسرب البيانات.
- `temperature` بلا تأثير حقيقي — مثال على متغير متاح لكنه غير مفيد.

### النموذج (محطة تعلم الآلة)
- انحدار لوغاريتمي-خطي حقيقي (Least Squares) يتدرب في المتصفح على بيانات المشارك وبخصائصه وإعداده. بالإعدادات الأفضل: خطأ ≈ ±2.3 على أسبوع الاختبار و≈ ±2.1 على أسبوع جديد كليًا.
- تحدي رمضان: النموذج القديم يخطئ ≈ ±13.6 في رمضان؛ بعد إضافة أول 4 أيام وخاصية «رمضان» لكل ساعة ينزل الخطأ إلى ≈ ±4.2 على الأيام 5–7.
- المقاييس المعروضة (متوسط الخطأ MAE، نسبة التوقعات ضمن ±5، MAPE، والمقارنة بطرق أبسط) **محسوبة فعليًا** — ومُعلَّمة بوضوح أنها على بيانات تعليمية غير حقيقية.
- مؤشر الحركة أثناء «التدريب» شكلي فقط؛ الحساب نفسه فوري.

### الحالة والحفظ
مفتاح التخزين: `decode-the-data:v3` مع ترحيل آمن من الإصدار السابق (`migrate` في `store.tsx`). يُحفظ: الشاشة الحالية، المحطات المكتملة، خطوة كل محطة واختياراتها، مخرجات كل محطة، تقييمات اكتشاف المسار، واسم المشارك (اختياري). لو التخزين غير متاح، التجربة تشتغل عادي لكن بدون استكمال.

## إمكانية الوصول والتصميم
- `dir="rtl"` و `lang="ar"` على مستوى الصفحة، مع `bdi`/`dir="ltr"` للأكواد والأوقات والمصطلحات الإنجليزية.
- كل التفاعلات أزرار حقيقية قابلة للتنقل بلوحة المفاتيح، مع حلقات تركيز واضحة ورابط «تخطَّ إلى المحتوى».
- يحترم `prefers-reduced-motion`.
- السحب والإفلات في لوحة BI له بديل بالضغط (يعمل على الجوال).
- تم اختبار عدم وجود تمرير أفقي على شاشة 390px لكل الشاشات.

## الاختبار الذي تم
- تشغيل كامل بنقرات حقيقية للمحطة الأولى (بما فيها الاختيارات الخاطئة والتلميحات وإعادة المحاولة) عبر Playwright.
- التنقل بين كل المحطات حتى النظام المكتمل، واستكمال التقدم بعد تحديث الصفحة.
- لقطات لكل الشاشات على سطح المكتب والجوال بدون أخطاء JavaScript.
- نسخة الورشة: التخطي التلقائي، نافذة «شوف نتيجة غلطتك» وزر الرجوع، القاموس، وشريط المقدّم.
- العمل بدون إنترنت: تحميل الموقع ثم قطع الشبكة وإعادة التحميل.
- **متبقٍّ عليكم:** تجربة الموقع مع شخص مبتدئ فعلًا قبل الورشة، وقياس الوقت في نسخة الورشة.

## افتراضات موثّقة
- مقدّم محطة ذكاء الأعمال: «يُعلن لاحقًا» — عدّلوه في `src/data/stations.ts`.
- قاعدة التوظيف: موظف لكل 8 طلبات في الساعة (`ORDERS_PER_STAFF` في `dataset.ts`).
- مستويات الازدحام: هادئ < 18، متوسط < 30، مزدحم < 45، ذروة شديدة ≥ 45 طلب/ساعة (`crowdLevel` في `model.ts`).
- اكتشاف المسار مبني على التفضيلات فقط (تقييم المهام + 3 أسئلة اختيار)، وليس اختبار قدرات، ويظهر ذلك للمشارك بوضوح.
- محتوى نظام حماية البيانات الشخصية تبسيط تعليمي (المرسوم الملكي م/19، إشراف سدايا، الموافقة الصريحة للتسويق المباشر) وليس استشارة قانونية.
- روابط خارطة الطريق (Kaggle Learn، سطر، أكاديمية طويق، أكاديمية سدايا/أذكى إكس، مسك، Microsoft Learn، Google ML Crash Course) — البرامج ومواعيدها تتغير، راجعوها قبل كل ورشة.
- تاريخ بداية رمضان 1447 تقريبي (18 فبراير 2026) ويُستخدم للقصة فقط.
- الشخصيات رسومات أصلية عامة تمثل الأدوار، وليست صورًا للمقدّمين.
